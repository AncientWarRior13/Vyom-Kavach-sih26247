# Standalone 31-Feature Experiment (Option B)

*Additive, non-breaking experiment. The frozen 11-feature schema, `final_model.joblib`,
and everything on `pair1-live-demo`/`pair1-reasoning` are untouched — this lives only
on the `feature31-standalone` branch.*

## What this is

A second, independent feature schema and model, built per `FEATURE_SCHEMAS.md` Section 3:
31 statistical features (mean/std/min/max/range/energy/zcr/dominant_freq/spectral_bandwidth/
diff_var, x3 channels — amplitude/velocity/energy — + snr_db) extracted from 100-sample raw
waveforms, instead of the 11 physics-derived point features the deployed model uses.

The waveform generator (`feat31_simulator.py`) reuses the exact same per-class physical
parameters as the frozen `simulator.py` (RCS ranges, micro-Doppler bandwidth/jitter, OU
velocity dynamics) so both schemas describe the same underlying targets — this makes the
comparison meaningful rather than two unrelated simulators being compared by coincidence.

**Deliberate design difference:** SNR range extended to [-25, -10] dB (vs. the frozen
schema's [-20, -10]), specifically so both schemas could be evaluated at -25 dB as asked.

## Pipeline

| Script | Purpose |
|---|---|
| `feat31_simulator.py` | Generates 100-sample amplitude/velocity/energy waveforms per class, SNR in [-25,-10]dB |
| `feat31_features.py` | Extracts the 31 named features from the waveforms |
| `feat31_train.py` | Trains CatBoost + class-weighting + **PR-curve/F-beta2 threshold tuning** (same full methodology as the incumbent, not just the model type) |
| `feat31_compare.py` | Evaluates the FROZEN 11-feature model on genuinely out-of-distribution -25dB data (generated by reusing `simulator.py`'s exact class physics, unmodified) |
| `feat31_plot.py` | SNR-sweep comparison plot |

## Self-correction, kept visible (not smoothed over)

Two real mistakes were made and fixed during this experiment, in order:

1. **First pass had no threshold tuning at all** (raw argmax) — a likely reason for the
   31-feature model's initially weak drone recall (71.8% at the -25dB slice). Fixed by
   reusing `radarsense.optimize`'s `tune_threshold`/`threshold_predict` (they operate on
   probability arrays only, not the feature schema, so directly reusable) — drone recall
   at that slice improved to 76.9%, with an honest precision/accuracy trade-off.

2. **The -25dB "out-of-distribution" test for the frozen model was miscalibrated** — its
   noise magnitude was computed against the EXTENDED [-25,-10]dB band, which meant
   noise_frac capped at exactly 1.0 at -25dB: the SAME maximum noise level the frozen
   model already saw at -20dB in training, not genuinely extrapolated noise. Fixed by
   computing noise_frac against the model's ACTUAL trained band (`C.SNR_RANGE_DB`,
   [-20,-10]), so -25dB now correctly produces noise_frac=1.5 (50% beyond anything the
   model was ever trained on) — the real meaning of "out-of-distribution." This changed
   the outcome of the comparison (see below) — the first version of this result was wrong
   and has been replaced, not kept alongside as an alternate answer.

## Results (corrected)

**Overall (31-feature model, own held-out test, n=7,800, tuned threshold t=0.33):**
96.6% accuracy, 0.878 macro-F1, 83.1% drone recall, 59.8% drone precision.

**At -25dB, genuinely out-of-distribution for the incumbent — the actual comparison asked for:**

| Model | Accuracy | Macro-F1 | Drone recall |
|---|---|---|---|
| 11-feature (frozen, unmodified, truly OOD at this noise level) | 95.1% | 0.870 | **88.2%** |
| 31-feature (trained for this regime, threshold-tuned) | **96.1%** | 0.842 | 76.9% |

**This is a genuine trade-off, not a clean win for either schema.** The 31-feature model
has higher overall accuracy under genuinely extrapolated noise; the incumbent has
meaningfully better drone recall specifically — and per this project's own established
cost framing (`config.py`: a missed drone costs 25x a false alarm), drone recall is the
metric that has always been treated as the headline number, not overall accuracy. Reporting
both, not picking whichever favors one side.

## Interpretation

The 31-feature model, once properly threshold-tuned, is a legitimate improvement over its
first (broken) version and is genuinely competitive at extreme out-of-distribution noise —
better overall accuracy than the incumbent under conditions the incumbent was never trained
for. It is not, however, a clean superior replacement: the incumbent's drone recall
advantage at the same noise level is real and matters under this project's own stated cost
priorities.

**Caveat, stated plainly:** this remains one experiment, one simulator design, one specific
stress-test slice (n≈1,500 each side). Worth exactly the evidence that scope implies, not
more.
